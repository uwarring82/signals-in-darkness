# Errata to the repository seed card v0.2 (4 Sept 2026)

`cards/repo-seed-v0.2.md` is left as written. Frozen means frozen: the card records what was
specified, and deviations are recorded here with supersession pointers rather than by editing it.

## E1 — `LICENSE-content` superseded by `LICENSES/` and a REUSE mapping

The card's Structure block specifies, at the repository root:

> `LICENSE-content            prose, cards, notes, figures, tables: CC BY 4.0 (SPDX: CC-BY-4.0)`

That file no longer exists under that name. The content licence text now lives at
`LICENSES/CC-BY-4.0.txt`, alongside `LICENSES/Apache-2.0.txt`, and the file-scoped mapping is
declared machine-readably in `REUSE.toml` at the repository root.

**Why.** The card's arrangement — Apache-2.0 for code, CC BY 4.0 for the evidence record — cannot
be expressed in `CITATION.cff`, because CFF reads a list of licences as OR over the whole cited
work rather than as file-scoped licensing. Declaring both there would have misstated the
repository. `CITATION.cff` therefore carries no `license` field, and REUSE carries the mapping
instead; REUSE requires the licence texts under `LICENSES/` named by SPDX identifier. The root
`LICENSE` is retained because GitHub detects a repository licence only from the root file, and a
test asserts it stays byte-identical to `LICENSES/Apache-2.0.txt`.

**No compatibility file was created.** A stub at the old path would make the stale name resolve
while hiding the change; the pointer belongs in the record, which is this entry.

Substance unchanged from the card: content remains CC BY 4.0, code remains Apache-2.0 pending the
`iontrap-dynamics` decision the card reserves. Only the file layout and the declaration mechanism
differ.

- Supersedes: `cards/repo-seed-v0.2.md`, Structure block, `LICENSE-content` line.
- Implemented in: `REUSE.toml`, `LICENSES/`, `README.md` (Cite), `tests/test_licensing.py`.

## E2 — first public release carries no DOI

The card's Decisions block states:

> Zenodo DOI at the first public release (concept DOI across versions), not before.

`repo-v0.1.0` is the first public release and has **no DOI**. Repository archiving was
deferred rather than connected before the release, so no concept DOI was minted.

**Consequence, recorded rather than glossed.** Zenodo archives a GitHub release only if the
repository was enabled *before* that release was created. `repo-v0.1.0` therefore cannot
receive a DOI retroactively; a later release would be the first archived one, and would carry
the concept DOI the card anticipated. That is a deviation from a taken decision, not a
postponement of it.

The FAIR "Findable" row and `CITATION.cff`'s citation message were amended to state the
deferral, so no document promises an identifier the release does not have.

- Supersedes: `cards/repo-seed-v0.2.md`, Decisions block, the Zenodo DOI line.
- Affects: `FAIR.md` (Findable), `CITATION.cff` (message), `README.md` (Cite).
