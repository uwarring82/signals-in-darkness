**Purpose:** Turn the existing working folder (two frozen cards, three execution notes plus errata, nine scripts, seven figures, one companion draft) into a versioned, reproducible, citable project archive — *before* the paper is written and *before* card v2.0 restates the thesis.

## Objective

A reader with the repository and a Python environment can, without contacting the author: read what was preregistered (v1.0), what changed and why (v1.1, v2.0), reproduce every number and figure cited in the execution notes from the recorded seeds, and see which statements are results, pilots, or open items.

## Non-goals

- No general-purpose simulator (card exclusion; unchanged).
- No thesis statement in the README until card v2.0 is frozen; the README carries the card status line and the results hierarchy from note 03a only.
- No rewriting of frozen cards or dated notes; corrections are errata files.
- No inclusion of the dark-matter, Lévy, network, or platform-survey material from earlier card drafts except as a dated `history/` record of the scope path.

## Rules

1. **Frozen means frozen.** Files under `cards/*-frozen.md` and dated notes are never edited after their tag; changes are new files (errata, next version).
2. **Every reported number is reproducible.** A number in a note must map to a run script, a seed, and an output file. If it cannot, it is marked `[unreproduced]` in the note's errata until fixed.
3. **Citation verification.** No reference enters `bibliography.bib` without a line in `verification.md`. Load-bearing references (those the prior-art boundary rests on) require full-text verification; context references require identifier resolution. The two Sakuldee–Cywiński papers (PRA 101, 012314 (2020); PRA 99, 062113 (2019)) enter as load-bearing and unverified until read.
4. **Session notes.** Each working session that changes analysis or cards gets a session note: date, scripts run, seeds, results in one line each, decisions taken, open items carried. This is the provenance trail between tagged states.
5. **Status vocabulary** (used in README, notes, and docs): *result* (reproduced, uncertainty stated, within a frozen card's scope), *pilot* (one operating point or unresolved calibration precision), *open* (specified but not run), *withdrawn* (with pointer to the errata line).
6. **Tags.** `card-v1.0`, `card-v1.1`, `note-03a`, then `card-v2.0`; a tag is placed when the file it names is frozen. Zenodo DOI minted at the first preprint, not before.
7. **Library migration.** A module moves to `iontrap-dynamics` only with its tests and a pinned version bump here; the run scripts import from the pinned version thereafter.
