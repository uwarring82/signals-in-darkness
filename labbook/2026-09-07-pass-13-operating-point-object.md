# 2026-09-07 — Pass 13: the parameters a result was computed at

**Question:** Can the operating point become an explicit immutable object without disturbing a single published number?
**Finding:** Yes, and the check is unusually clean. A full fresh calibration of all seven pilot policies after the refactor reproduces the five valid rows at **0.00 σ with exact threshold equality**, while the two rows withdrawn as C17 fail exactly as they must — `oracle-mid(tc=20)` at 4.671875 against an archived 4.359, and `learner-interleave-B10(bank)` at 3.734375 against 3.55. Five pass, two fail, and the two that fail are the two that should. The run was on python 3.9.7 / numpy 1.23.5, not the pinned stack, so the refactor is inert across two environments rather than one.
**Why it matters:** The mutable `C, s = 0.4, 0.5` globals were not a style complaint. A stored result did not carry the parameters it was computed at: a calibration checkpoint recorded seeds, revision, interpreter and library versions, and said nothing about the operating point, so a threshold measured at one could be consumed by a delay run at another with nothing able to notice. That is the shape of the failure that cost C17 and C18. The operating point now enters `cal_config()` and therefore `config_digest`, and reuse under a different one is refused **by name** — verified end to end by tampering a checkpoint and watching `sid_run6s.py delays` exit 2 printing both operating points side by side. A companion test asserts identical configurations still compare compatible, because a gate that rejects everything is not a gate.
**Status:** No claim changed; the refactor is numerically inert by construction and by measurement. Roadmap G complete.
**Next test:** B, at C_eff = 0.5, s = 0.3 — the parity-ceiling stress point — with every policy calibrated afresh and no archived C17/C18 threshold entering.

Technical record: notes/2026-09-07-note-17-roadmap-G.md. `OperatingPoint` is a frozen dataclass carrying `C_eff` and `s`; the field is deliberately not `C_bar` and not `C_0`, with a test asserting both are absent so decision D1's distinction cannot erode back into a shared field. `Bank` and `build_policies` raise `TypeError` naming roadmap G when handed nothing or the wrong type, `run_batch` reads from the bank, and the module-level names are gone — asserted as absent attributes, as an absent assignment line, and as absent from every run's import list. Two smaller repairs came with it. `sid_fig_policy_delays.py` had the operating point in a title string literal and now reads it from the stored run's metadata; since the archive predates G and carries none, the rebuilt figure reads "operating point not recorded in this output", which is the honest rendering of a pre-G artefact rather than a literal the archive cannot support. And one assertion I had written into the acceptance tests was vacuous — `assert ... or True` — so it was replaced by a behavioural check that two banks differing only in operating point give different null run lengths and different delays. A test that cannot fail is the exact defect this repository's own lessons list first.
